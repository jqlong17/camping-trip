# 露营之旅本地性能测试记录

## 2026-08-30

### 测试环境

- macOS 本机
- LÖVE 11.5
- 项目：`/Users/ruska/projects/3ds/linjian`
- 测试入口：`love game --playtest`
- 自动流程覆盖标题、序章、角色选择、出发、营地、移动、道具仪式、夜间、回家、图鉴和关于页。

### 测试命令

完整动态效果：

```bash
love game --playtest
```

静态诊断模式：

```bash
LINJIAN_PLAY_FX=static love game --playtest
```

两组测试均以 `PASS` 结束。

### 结果

| 模式 | 营地 5 秒帧数 | 慢帧 | 最大帧耗时 | 营地资源加载 |
|---|---:|---:|---:|---:|
| `full_play_fx` | 582 | 0 | 46.9 ms | 11.7 ms |
| `static_play_fx` | 581 | 0 | 34.1 ms | 12.0 ms |

本地完整动态模式和静态模式几乎没有差异。电脑端没有复现进入营地的长时间等待，也没有复现持续低帧或音乐卡顿。

### 与 3DS 日志对照

此前 3DS 营地日志为：

```text
perf scene=play frames=22 slow=22 maxDtMs=约250ms
```

即约 4 FPS，而本地约为 116 FPS。两者差距很大，说明问题主要依赖 3DS 的运行环境，不能用桌面 LÖVE 的帧率直接代表真机表现。

当前最可能的范围是：

1. 3DS 对大量独立纹理 `draw` 调用的处理成本。
2. LovePotion 纹理/显存路径与桌面 LÖVE 的差异。
3. 真机画面线程长时间阻塞，导致 `stream` 音频补充不及时。

动态效果在电脑上的成本很低，但仍需以已部署的 `static_play_fx` 真机版本作最终隔离实验。若静态真机仍约 4 FPS，应优先减少静态地图的每帧绘制调用，而不是继续调整风效或音乐格式。

### 本轮代码诊断支持

`game/main.lua` 增加了：

- `LINJIAN_PLAY_FX=static` 本地开关。
- 桌面 playtest 的 `load_report.txt`。
- `camp_load_begin` 和 `ensureCamp done ... durationMs=...`。
- `perf` 行中的 `mode` 字段。

本地日志位置：

```text
~/Library/Application Support/LOVE/camping-trip/load_report.txt
```

真机日志位置：

```text
SD:/3ds/CampingTrip/save/camping-trip/load_report.txt
```

### 结论

本地测试可以提前验证逻辑、资源完整性、场景流程和桌面端负载，但无法替代 3DS 对 GPU 绘制、纹理上传、SD 读取和音频流的测试。当前下一步仍应以 `static_play_fx` 真机日志为依据：先确认关闭动态效果后是否恢复帧率，再决定是否重构地图渲染。
