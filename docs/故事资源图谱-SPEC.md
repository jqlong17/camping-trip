# 露营之旅 · 故事资源图谱 SPEC

> 状态：DEV-096 · 本地开发工具，不进入 LovePotion RomFS。

## 1. 目标

在一个可缩放、可搜索的关系画布中同时回答：

1. 玩家从标题开始，按 A 或选择菜单后会到哪里。
2. 每个场景、分镜和仪式使用了哪些运行时资源。
3. 资源的原图、生成参考、构建脚本和本地文件在哪里。
4. 哪些剧情断开、资源缺失、未关联、遗留或需要重做。
5. 人与 Agent 能否用稳定编号准确讨论同一个对象。

## 2. 范围

首版覆盖：

- 标题、开始/继续、选角、图鉴、关于与返回确认。
- 序章 `p1–p3`、出发 `d1–d2`、回家 `h1`。
- 营地时间线、回家条件，以及帐篷、手冲、泡茶、钓鱼、杯子、做饭。
- 三页动态日记和保存后回到标题。
- `game/assets`、`game/audio`、`game/fonts`、`cia` 中的运行时媒体。
- `docs/promo`、`docs/storyboards` 中可作为制作源的图片。

不改变游戏代码，不把网页依赖或索引文件打进 3DS 包。

## 3. 实体与编号

编号是永久身份，不使用数组下标。

| 前缀 | 实体 | 示例 |
|---|---|---|
| `SCN` | 场景 | `SCN-001` 标题 |
| `BEAT` | 叙事分镜 | `BEAT-001` 周末到了 |
| `CHO` | 选择/条件 | `CHO-001` 是否已有角色 |
| `ACT` | 营地动作或仪式 | `ACT-002` 手冲 |
| `PHASE` | 仪式步骤 | `PHASE-001` 手冲选豆 |
| `PAGE` | 日记页 | `PAGE-001` 这次的周末 |
| `CODEX` | 装备图鉴条目 | `CODEX-001` 帐篷 |
| `RES` | 媒体资源 | `RES-0127` |

剧情对象在 `story-manifest.json` 中显式编号。媒体资源路径与 `RES` 编号写入
`resource-registry.json`：新增路径只领取下一个号码；删除后保留 tombstone，禁止复用。

## 4. 关系

- `next`：无条件推进。
- `input`：按键、触摸或菜单操作。
- `choice`：玩家选择。
- `condition`：存档、时间、位置或收获条件。
- `branch`：可选玩法分支。
- `browse`：从图鉴等集合页浏览一个条目，不进入实际玩法。
- `return`：完成后回到父流程。
- `uses`：剧情或玩法使用媒体资源。
- `derived_from`：运行时资源来自原图或生成参考。

`derived_from` 只允许来自资产构建脚本中的 `ASSET_PROVENANCE` 静态声明。声明必须同时给出输出路径、仓库内制作源、处理脚本和处理方式（如 `slice_grid`、`crop`、`resize`、`quantize`）；扫描器通过 AST 读取声明，不导入或执行构建脚本。禁止再用文件名相似度推测来源。没有声明时显示“来源未登记”，代码直接绘制的资源明确标记为 `procedural`。

权威流程来自 `game/scene_flow.lua`、`game/input.lua`、`game/scenes/story.lua`；
图谱 manifest 负责把代码语义变成人能阅读的节点和连线。

SCN-003 的水系血缘必须完整串起 `docs/promo/creek_*_ref.png` →
`scripts/build-creek-tiles.py` → 深水/浅水/8 向岸线 PNG →
`scripts/build-camp-static-base.py` → `camp_static_base.png`。场景布局只在陆地格登记
岸线 overlay；水格不得重复登记同一岸片，深浅水变体须与静态烘焙的空间取样一致。

## 5. 展示规则

- 默认只显示主线，保持约 15 个节点可读。
- “含玩法”会展开营地下屏六件装备、图鉴六个独立条目，以及手冲 7 步、泡茶 7 步、钓鱼 6 步、品杯 2 步、做饭 5 步；步骤内的选项只作为标签，不拆成节点。
- 所有节点都能自由拖拽，位置按主线/含玩法/全部三个层级分别保存在浏览器本地。
- 全量资源在左侧分层浏览，不默认平铺到画布。
- 选中节点后显示编号、说明、触发方式、资源、代码来源和上下游关系。
- 图片使用硬像素缩放；分镜按 3DS 有效区 400×240 预览。
- PNG 可预览原图，MP3/WAV 可播放，T3X 作为 PNG 的 3DS 派生状态显示。

## 6. 本地文件能力

网页通过本地 Vite 服务运行。受限接口可以：

- 读取仓库白名单目录内的图片、音频和文本。
- 在 Finder 中定位文件。
- 复制稳定编号和仓库相对路径。

接口必须拒绝绝对路径、`..`、符号链接逃逸和仓库外路径。静态构建不承诺 Finder 定位。

## 7. 状态与审计

资源状态：

- `active`：运行时使用或明确关联。
- `unlinked`：存在但尚未建立代码/剧情关联，可能是动态加载。
- `legacy`：旧体系或已替代资源。
- `backup`：备份目录资源。
- `missing`：manifest 或代码引用不存在。
- `review` / `remake`：人工质量标记。

审计必须报告：

- 断开的剧情边和不存在的节点。
- 缺失媒体与失效制作源。
- 重复编号或路径。
- PNG/T3X 配对缺失。
- 未关联、遗留和备份资源数量。
- 没有预览图的剧情节点。

## 8. 数据生成

```bash
python3 scripts/scan-story-atlas.py
cd tools/story-atlas
npm run dev
```

扫描结果写入 `tools/story-atlas/public/graph-index.json`。每次修改剧情、资源或 manifest 后重跑扫描。

## 9. 验收

- 可从 Logo/标题沿连线走完整局并回到标题。
- `p1–p3`、`d1–d2`、`h1` 与三页日记都可单独定位。
- 输入任一 `SCN/BEAT/ACT/PAGE/RES` 编号可找到对象。
- 资源详情能查看运行时图、制作源和引用节点。
- Finder 定位只允许仓库内文件。
- 扫描、测试、类型检查和生产构建通过。
